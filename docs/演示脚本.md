录制要求（课程要求）：一次录屏、无跳步、无剪辑拼接，能看清页面上的数值；片头写明项目编号 26 与成员，片尾展示提交包目录结构。
建议分辨率 1920×1080，浏览器缩放 100%，先按下面“准备”把数据重置成干净状态。

## 准备（录屏前，不要录进视频）

```powershell
# 1) 重置数据库（1 间自习室、10 个座位、7 个账号、单价 4.00）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\reset_db.ps1

# 2) 云函数本地模拟（演示“金额来自云端计算”）
python scripts\mock_fg.py

# 3) 后端（新终端；FG_ENDPOINT 指向本地模拟器，页面上来源会显示 CLOUD）
set FG_ENDPOINT=http://127.0.0.1:9100/billing
java -jar backend\target\studyroom-backend-1.0.0.jar

# 4) 前端（新终端）
cd src\frontend && npm run dev
```

浏览器打开 `http://127.0.0.1:5173/`，先用 s001（口令 123456）登录。

## 讲的时候要点到的三个易错点

1. **重复处理不二次扣费**：第 2 步故意点两次手工触发；账单与信用流水都只增加一条（唯一键 `bill_order(reservation_id, kind)` 与 `credit_log.idem_key`）。
2. **规则不叠加**：月卡用户、包天卡用户签退时金额分别是 0.00 与 30.00/0.00，不会再叠加按分钟的费用。
3. **涨价只作用于涨价之后新开始的使用**：第 10 步最后用一个“涨价前开始”的使用签退，金额仍按 4.00 计算。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面显示金额来源为 LOCAL | 后端启动前没设 `FG_ENDPOINT`，或 `scripts/mock_fg.py` 没启动；重启后端即可 |
| 座位都变成“使用中” | 演示数据脏了，重新执行 `scripts\reset_db.ps1`（会清空并回到 10 个空闲座位） |
| 登录后在别的页面看不到数据 | 确认后端 8080 在跑；Vite 只在 `/api` 前缀上做代理 |
| 端口被占用 | 5173 被占时 Vite 会自动换端口；8080 被占则先结束旧的 java 进程 |
